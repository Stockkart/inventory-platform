# @inventory-platform/attendance-protocol

**Status:** Active

Wire types and pure helpers shared by the Attendance app (`apps/attendance`) and the manager HR UI (`core/hr`) for the biometric attendance feature (`.kiro/specs/HR-module`). Pure TypeScript: no React, no fetch, no browser or React Native API.

## Owns

- `src/types.ts` — mirrors of the `inventory-api` `core/hr` DTOs for the app endpoints (`ClaimPairingRequest`, `CompletePairingRequest`, `PairingBootstrap`, `AppStatusResponse`, `AppPunchRequest`, `AppPunchResponse`, `PunchResponse`, `PairingStateResponse`, `PairingCodeResponse`, `AppHealthResponse`) with string-literal unions for `PunchSource`, `PunchFlag`, `AttendanceSource`, `PairingStatus`, `UnpairReason`, `ManualMarkReason`, `DeviceOs`
- `fixtures/canonical.json` — generated by the Java `AppSignatures` tests in `inventory-api` (`core/hr/src/test/resources/attendance-protocol/fixtures/canonical.json`). Do not edit by hand; copy the regenerated file when the Java side changes. The TypeScript canonical builders assert byte equality against it.
- `src/canonical.ts` — `canonicalPunchPayload()` / `canonicalRequestEnvelope()` (`SKAT-PUNCH-1` / `SKAT-REQ-1`, byte-identical to Java `AppSignatures`), `sha256Hex()` (WebCrypto `crypto.subtle`, or an injected digest such as `expo-crypto` on runtimes without it), `formatPhoneTime()`, hex helpers
- `src/pairing-code.ts` — `PAIRING_CODE_ALPHABET`, `normalisePairingCode()`, `isPairingCode()`, `pairingQrPayload()`, `pairingCodeFromScan()` (QR URL `https://stockkart.in/attendance/pair#<CODE>` or bare code), mirror of Java `PairingCodes`
- `src/messages.ts` — the refusal and flag sentences the app shows word for word (`SERVER_MESSAGES` by `ErrorCode` name, `FLAG_SENTENCES`, R7.10 helpers, confirmation and offline lines)

## Boundaries

- Nx tags `type:platform`, `scope:attendance`. `scope:attendance` may depend on `scope:attendance` and `type:platform` only (root `eslint.config.mjs`).
- Nothing here may import `ui-kit`, `api-client`, `session`, `routing` or any `core/*` package: the Expo app cannot load them.

## Tests

`vite.config.mts` is test-only (vitest, node environment; fast-check from the workspace root for property tests). Run `pnpm exec nx test attendance-protocol` or `./node_modules/.bin/vitest run --root platform/attendance-protocol --config vite.config.mts`.

## Does not own

- Calling the endpoints (`apps/attendance/src/api/appClient.ts`, `core/hr/src/api/pairing.api.ts`)
- The biometric signer (`apps/attendance/modules/biometric-signer`)
- Register / settings types that only `core/hr` uses (`core/hr/src/model`)
